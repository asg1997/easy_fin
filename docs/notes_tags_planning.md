# Теги для заметок (v1)

## Цель

Добавить к заметкам **простую систему тегов**:

- у заметки может быть 0+ тегов;
- теги можно добавлять и снимать;
- сверху списка — фильтр по тегам (показать заметки с выбранным тегом).

Без папок, цветов, вложенности и «умных» правил.

---

## Почему это возможно

Заметки уже в SQLite и уезжают на GitHub вместе с файлом БД. Теги кладём в ту же БД → они синхронизируются автоматически, отдельно sync писать не нужно.

TODO тегами **не** трогаем (остаются локальными и без тегов).

---

## Принятые решения (предложение v1)

| Вопрос | Решение |
|--------|---------|
| Где хранить | SQLite (Drift), рядом с `notes` |
| Sync | Да — через файл `easy_fin.sqlite` |
| Модель данных | Таблица связей `note_tags` (noteId + имя тега), без отдельного справочника тегов |
| Имя тега | Строка 1–40 символов, trim; сравнение **без учёта регистра** |
| Нормализация | Храним в том виде, как ввели (после trim), ищем case-insensitive |
| Сколько тегов на заметку | Без жёсткого лимита (разумный UX: обычно 1–5) |
| Пустые теги | Нельзя |
| Удаление тега «из системы» | Отдельного экрана нет: тег исчезает из фильтра, когда ни у одной заметки его больше нет |
| Фильтр | Один выбранный тег **или** «Все»; логика: заметка **содержит** тег |
| Несколько тегов в фильтре сразу (AND/OR) | Не в v1 |
| Цвета / иконки тегов | Не в v1 |
| Теги в TODO | Не в v1 |

### Почему без справочника `tags`

Для v1 достаточно:

```text
note_tags(note_id, tag_name)  PRIMARY KEY (note_id, tag_name)
```

- список для фильтра: `SELECT DISTINCT tag_name …`
- заметки по тегу: join / where по `tag_name`
- переименовать тег глобально и «управление тегами» — не нужны

Если позже понадобится rename/merge — добавим таблицу `tags` и миграцию.

## Модель данных

### Таблица Drift

```dart
/// Связь заметка ↔ тег (sync через файл БД)
@DataClassName('NoteTagRow')
class NoteTags extends Table {
  TextColumn get noteId =>
      text().references(Notes, #id, onDelete: KeyAction.cascade)();

  TextColumn get tagName => text()();

  @override
  Set<Column> get primaryKey => {noteId, tagName};
}
```

Миграция: `schemaVersion` 16 → **17**, в `onUpgrade` при `from < 17` — `migrator.createTable(noteTags)`.

### Domain

```dart
class Note {
  // ...как сейчас
  final List<String> tags; // отсортированный список имён
}
```

## Поведение

| Действие | Поведение |
|----------|-----------|
| Добавить тег к заметке | Ввод имени → trim → если такого ещё нет у заметки — insert в `note_tags` |
| Убрать тег | DELETE строки связи |
| Создать заметку | Можно сразу без тегов; теги — после или в том же блоке UI |
| Удалить заметку | CASCADE удаляет её теги |
| Фильтр «Все» | Все заметки, как сейчас (`updatedAt` desc) |
| Фильтр по тегу | Только заметки, у которых есть этот тег |
| После мутаций | `invalidate(notesListProvider)` + `invalidate(githubSyncDirtyProvider)` (+ провайдер списка тегов) |

## UI (черновик)

```
┌─────────────────────────────────────────────┐
│  [ Новая заметка…                        ]  │
│                                             │
│  Теги:  [ Все ]  [ аренда ]  [ важно ] …    │  ← чипы фильтра
│                                             │
│  20 авг 2026                        🗑      │
│  #аренда  #важно                            │  ← теги заметки (мелкие)
│  Текст заметки…                             │
└─────────────────────────────────────────────┘
```

### Фильтр

- Горизонтальный ряд чипов под полем новой заметки.
- Первый чип: **Все** (выбран по умолчанию).
- Остальные — `DISTINCT` теги, по алфавиту (или по частоте — на усмотрение реализации; v1: алфавит).
- Один активный фильтр за раз.

### Теги на карточке заметки

- Под датой / рядом с датой — мелкие метки `#имя` или компактные чипы.
- Добавление: поле «+ тег» или ввод с подтверждением Enter / ⌘Enter.
- Снятие: крестик на чипе или повторный тап.

### Новая заметка

- В v1 теги можно вешать **после** создания (проще).
- Опционально: строка тегов под композером — если успеем без усложнения.

### Провайдеры

| Провайдер | Роль |
|-----------|------|
| `notesTagFilterProvider` | `String?` — `null` = все, иначе имя тега |
| `allNoteTagsProvider` | `FutureProvider<List<String>>` — distinct теги |
| `notesListProvider` | Список заметок; при фильтре — только с выбранным тегом |

После sync (download) — инвалидировать `notesListProvider` и `allNoteTagsProvider` (добавить в `_invalidateAppDataProviders`).

## Открытые вопросы (решено при реализации)

1. **Регистр:** храним и показываем как ввели (после trim), фильтр case-insensitive.
2. **Добавление тега:** только у уже сохранённой заметки.
3. **Символы:** пробелы разрешены; ведущий `#` снимается при вводе; пустая строка запрещена.
